# Pilot results, October 2026

Three teams of Claude Haiku 5.5 agents (Claude Code 2.1.310) ran on the same 48 fresh tasks.
Both teams resolved one or two more tasks than a single agent, which is not significant, at 1.6×
and 2.7× its model cost.

| Team | Spec | Resolved | Rate (95% CI) | Mean model cost/task | Model + solve sandbox cost/task | Median wall time |
|---|---|---|---|---|---|---|
| solo | `solo:worker=claude@claude-haiku-5-5` | 27/48 | 56.2% (42.3%–69.3%) | $0.061 | $0.115 | 77 s |
| review | `review:coder=…,reviewer=…` (3 rounds) | 29/48 | 60.4% (46.3%–73.0%) | $0.098 | $0.220 (1.9× solo) | 3.3 min |
| best of 3 | `best:workers=…+…+…` (Haiku judge) | 28/48 | 58.3% (44.3%–71.2%) | $0.167 | $0.469 (4.1× solo) | 4.4 min |

Paired against solo on the same tasks, review won 2 and lost none (+4.2 points, 95% CI −2.7
to +10.9, exact McNemar p = 0.5), and best of 3 won 2 and lost 1 (+2.1 points, −5.9 to +10.0,
p = 1.0). With 48 tasks a gap this size is not detectable; the intervals put either team's gain
under 11 points.

!!! note "Re-graded on 2026-11-01 (US Pacific)"
    The first version of this page reported 20, 19 and 17 resolved tasks. The grader then counted
    a patch as unresolved whenever any of its hunks failed to apply. In this run all 49 patches
    that failed to apply were rejected only in files the hidden test patch also changes: the
    agents had added their own tests there. The official SWE-bench-Live grading leaves those
    files to the hidden tests and grades on the tests alone, and so does the runner now. The
    stored logs were re-graded with that rule; no agent was re-run. It changed 7 solo, 10 review
    and 11 best-of-3 verdicts from unresolved to resolved, all of them patches whose tests pass.
    Each record's `eval.regraded` carries the UTC date, 2026-11-02.

## Why the teams barely helped

- **Asking for changes made no difference.** The reviewer approved the coder's
  first patch on 39 of 48 tasks and in the end approved 47; 19 of those 47 do not resolve the
  task. On the 9 tasks where it asked for changes, review and solo resolved exactly the same 5.
  Review's two wins over solo (`langchain4j__langchain4j-5806` and `-5869`) are first patches
  the reviewer approved unchanged, so they came from a different coder rollout, not from review.
- **The judge rarely tells candidates apart.** It scores each candidate on its own, and its top
  score was tied between two or three candidates on 32 of 48 tasks. The runner breaks a tie by
  taking the earliest candidate, so candidate 1 was picked on 29 tasks. Candidates were not graded
  one by one, so how often a resolving one was passed over is not known.
- **No headroom across teams.** At least one team resolved 29 of the 48 tasks, the same as review
  alone. Both teams' wins are the same two tasks.

## Setup

- **Tasks.** [SWE-bench-Live MultiLang](https://huggingface.co/datasets/SWE-bench-Live/MultiLang),
  created on or after 2026-07-01, after the June 2026 training cutoff Anthropic documents for its
  current models. A seeded sample of 70 (seed 7) was validated with the reference patches on Modal:
  48 valid, 21 invalid (the reference fix fails there, for example c-ares' IPv6 tests), 1 grading
  error. The pilot ran on the 48 valid tasks.
- **Grading.** The dataset's hidden tests and log parsers in a clean sandbox of the instance image,
  ported line for line from SWE-bench-Live; agents never see the tests or the grader's output. See
  [the benchmark guide](../agent/bench/README.md).
- **Runtime.** Modal sandboxes (4 vCPU, 16 GB), driven by a detached Modal function
  (`python -m agent.bench remote run ...`), 2026-10-29 and 2026-10-31. One rollout per task and
  team; no pair errored or timed out (the longest solve took 48 minutes, the limit was 60).
- **Cost** is Claude Code's own `total_cost_usd` at API list prices: $15.67 for the 144 pairs.
  Modal compute is not included in it. The table's sandbox column adds the solve's sandbox-hours
  (3.8, 8.8 and 21.7) at Modal's $0.668 per hour; see the report's *Compute* section.

## Interruption and resume

On 2026-10-29 at 19:09 UTC the Anthropic key reached its usage limit. From then on every agent
exited after about two seconds with `API Error: 400 You have reached your specified API usage
limits`. Those pairs were marked as errors, with the rule the runner now applies itself (#92: a
failed agent run that used no input or output tokens), plus one pair whose agent the limit cut off
mid-run. After the limit was lifted, the same command resumed on 2026-10-31: it skipped the 34
finished pairs and ran the other 110. Every pair in the table is a complete run; the superseded
error records stay in `results.jsonl.gz` for audit.

## Data

Everything is in
[`results/2026-10-haiku-pilot/`](https://github.com/BichengWang/multi-agents/tree/main/results/2026-10-haiku-pilot):

| File | Contents |
|---|---|
| `report.md` | The report from `python -m agent.bench report` |
| `results.jsonl.gz` | Every attempt per task × team (the latest one counts): patch, usage, cost, timing, grading details, errors |
| `artifacts.tar.gz` | `artifacts/<team>/<task>/`: the final patch (`patch.diff`); each agent run's final message, usage, duration and a `turns=N stop=…` line (`runs.json`); the grading log (`eval.log`). Not trajectories: tool calls, their output and intermediate patches were not kept |
| `gold.jsonl` | Reference-patch validation of the 70 sampled tasks |
| `meta.json` | Filters, seed, dataset revision, teams and budget of each invocation |

To regenerate the report:

```bash
mkdir pilot && cd pilot
cp ../results/2026-10-haiku-pilot/meta.json . && gunzip -c ../results/2026-10-haiku-pilot/results.jsonl.gz > results.jsonl
python -m agent.bench report . --baseline solo:worker=claude@claude-haiku-5-5
```

Stored text was scrubbed of credentials before writing (values of credential variables and
key-shaped strings), and the data was scanned again for the key before publishing. The
`[REDACTED]` marks in it are false positives: test logs, and code from a task about masking
credentials.
