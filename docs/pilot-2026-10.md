# Pilot results, October 2026

Three teams of Claude Haiku 5.5 agents (Claude Code 2.1.310) ran on the same 48 fresh tasks.
Neither team beat a single agent; both cost more.

| Team | Spec | Resolved | Rate (95% CI) | Mean cost/task | Median wall time |
|---|---|---|---|---|---|
| solo | `solo:worker=claude@claude-haiku-5-5` | 20/48 | 41.7% (28.8%–55.7%) | $0.061 | 77 s |
| review | `review:coder=…,reviewer=…` (3 rounds) | 19/48 | 39.6% (27.0%–53.7%) | $0.098 | 3.3 min |
| best of 3 | `best:workers=…+…+…` (Haiku judge) | 17/48 | 35.4% (23.4%–49.6%) | $0.17 | 4.4 min |

Paired against solo on the same tasks, review won 3 and lost 4 (−2.1 points, exact McNemar
p = 1.0), and best of 3 won 2 and lost 5 (−6.2 points, p = 0.45). With 48 tasks a gap this size
is not detectable either way; what the data does show is that the extra agents did not buy a
measurable gain at this model tier, while review cost 1.6× and best of 3 2.8× as much per task.

## Why the teams did not help

- **The reviewer approves almost everything.** It accepted the coder's first patch on 39 of 48
  tasks and ended up accepting 47. Of those 47 approved patches, 29 fail the hidden tests. On the
  9 tasks where it asked for changes, review resolved 3 and solo resolved 4: every task review
  solved there, solo solved too, and on `xroche__httrack-810` the revised patch lost a solve.
- **The judge rarely tells candidates apart.** Its top score was tied between two or three
  candidates on 32 of 48 tasks, and the first candidate was picked on 29, so the pick is mostly by
  position. Candidates were not graded one by one, so how often a passing one was passed over is
  not known.
- **Rollouts differ more than teams.** At least one team resolved 24 of the 48 tasks, while the
  best single team resolved 20. The 4 extra tasks were each solved by a team's rollout and missed
  by solo's. That headroom is what a better reviewer or judge, or an objective check, would have
  to capture.

## Setup

- **Tasks.** [SWE-bench-Live MultiLang](https://huggingface.co/datasets/SWE-bench-Live/MultiLang),
  created on or after 2026-07-01, after the June 2026 training cutoff Anthropic documents for its
  current models. A seeded sample of 70 (seed 7) was validated with the reference patches on Modal:
  48 valid, 16 invalid (the reference fix fails there, for example c-ares' IPv6 tests), 6 grading
  errors. The pilot ran on the 48 valid tasks.
- **Grading.** The dataset's hidden tests and log parsers in a clean sandbox of the instance image,
  ported line for line from SWE-bench-Live; agents never see the tests or the grader's output. See
  [the benchmark guide](../agent/bench/README.md).
- **Runtime.** Modal sandboxes (4 vCPU, 16 GB), driven by a detached Modal function
  (`python -m agent.bench remote run ...`), 2026-10-29 and 2026-10-31. One rollout per task and
  team; no pair errored or timed out (the longest solve took 48 minutes, the limit was 60).
- **Cost** is Claude Code's own `total_cost_usd` at API list prices: $15.67 for the 144 pairs.
  Modal compute is not included.

## Interruption and resume

On 2026-10-29 at 19:09 UTC the Anthropic key reached its usage limit. From then on every agent
exited after about two seconds with `API Error: 400 You have reached your specified API usage
limits`. Those pairs were marked as errors, with the rule the runner now applies itself (#92: a
failed agent run that used no input or output tokens), plus one pair whose agent the limit cut off
mid-run. After the limit was lifted, the same command resumed on 2026-10-31: it skipped the 34
finished pairs and ran the other 110. Every pair in the table is a complete run; the superseded
error records stay in `results.jsonl.gz` for audit.

## Data

Everything is in
[`results/2026-10-haiku-pilot/`](https://github.com/BichengWang/multi-agents/tree/main/results/2026-10-haiku-pilot):

| File | Contents |
|---|---|
| `report.md` | The report from `python -m agent.bench report` |
| `results.jsonl.gz` | Every attempt per task × team (the latest one counts): patch, usage, cost, timing, grading details, errors |
| `artifacts.tar.gz` | Raw trajectories: `artifacts/<team>/<task>/{patch.diff,runs.json,eval.log}` |
| `gold.jsonl` | Reference-patch validation of the 70 sampled tasks |
| `meta.json` | Filters, seed, dataset revision, teams and budget of each invocation |

To regenerate the report:

```bash
mkdir pilot && cd pilot
cp ../results/2026-10-haiku-pilot/meta.json . && gunzip -c ../results/2026-10-haiku-pilot/results.jsonl.gz > results.jsonl
python -m agent.bench report . --baseline solo:worker=claude@claude-haiku-5-5
```

Stored text was scrubbed of credentials before writing (values of credential variables and
key-shaped strings), and the data was scanned again for the key before publishing. The
`[REDACTED]` marks in it are false positives: test logs, and code from a task about masking
credentials.
